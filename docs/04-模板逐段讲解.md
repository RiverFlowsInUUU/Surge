## 1. `[General]` 段

### 1.1 DNS 组（六行，缺一不可）

```
dns-server = 223.5.5.5, 119.29.29.29, 1.1.1.1, 8.8.8.8
encrypted-dns-server = https://1.1.1.1/dns-query, https://dns.google/dns-query, https://dns.alidns.com/dns-query
encrypted-dns-follow-outbound-mode = false
hijack-dns = 8.8.8.8:53, 8.8.4.4:53, 1.1.1.1:53, 1.0.0.1:53, 9.9.9.9:53, 208.67.222.222:53
exclude-simple-hostnames = true
read-etc-hosts = true
```

| 键 | 为什么是这几个值 |
|---|---|
| `dns-server` | 写**裸 IP**。它只在两种情况下被用到：给加密 DNS 端点做引导、以及给加密 DNS 端点做连通性测试。**绝不能写 `system`** —— 那正是要消除的那条通路。 |
| `encrypted-dns-server` | 三个端点跨两个机构（Cloudflare + Google + 阿里）。**端点的 IP 部分写了字面量**，所以启动期不需要解析它们。 |
| `encrypted-dns-follow-outbound-mode` | `false` = 加密 DNS 连接走直连。`true` 会让 DoH 连接遵循代理规则 ⇒ 解析代理本身需要代理 ⇒ **启动期成环**。 |
| `hijack-dns` | 接管硬编码解析器。忽略 Surge DNS 的设备（HomePod / Apple TV / 智能音箱）会直接发 `8.8.8.8:53`，这一行把它们拉回来。 |
| `exclude-simple-hostnames` | 单标签主机名（`printer`、`nas`）不做 DNS，直接交给系统 —— 减少无意义的查询。 |
| `read-etc-hosts` | 尊重本地 hosts。**只对 DIRECT 路径生效**，见下面 `use-local-host-item-for-proxy`。 |

> ⚠️ **本模板的两处刻意取舍**（用 `# audit-waive:` 在原文件里声明）：
> 1. `https://dns.google/dns-query` 与 `dns.alidns.com` 是**主机名形式**，会被引导解析一次。
>    想彻底消掉就换成 IP 字面量（`https://8.8.8.8/dns-query`、`https://223.5.5.5/dns-query`），
>    代价是失去「按域名走 CDN 就近解析」与「ECS 合规」两项收益。
> 2. 兜底指向 `Proxy` 而非国内组 —— 本模板不做分流兜底的境内 / 境外切分。

### 1.2 本地映射

```
use-local-host-item-for-proxy = false
```

保持 `false`。开启后本地 DNS 映射会成为**硬性代理目标** —— 走代理的域名本该由节点远端解析，
本地不该有它的答案。开了会破坏远端解析。

### 1.3 IPv6

```
ipv6 = true
ipv6-vif = auto
```

`ipv6 = true` 让真实 IPv6 站点可直连。
`ipv6-vif = auto` 只在本地网络**确实有**可用 IPv6 前缀时才让 VIF 承载 IPv6 ——
避免在纯 IPv4 的 Wi-Fi 上留一条死掉的 AAAA 路径（表现是连接超时 + 额外耗电）。

### 1.4 测试端点（**性能探针，不是泄露通道**）

```
internet-test-url = http://connect.rom.miui.com/generate_204
proxy-test-url = http://www.gstatic.com/generate_204
proxy-test-udp = apple.com@1.1.1.1
```

- ⭐ **`proxy-test-url` 保持境外 `gstatic.com`**。它是给 `smart` / `url-test`
  打分用的**性能探针**，量的是「本机 → 测试地址 → 节点 → 回来」整圈。
  境外端点含国际段，**与你实际访问境外站点的体感相关** —— 这才是有用的评分输入。
  换成境内端点测的是境内 RTT，**不是更准，是测了另一个东西**。
- ⭐ 那「周期性解析」呢？官方 KB 明确：走代理策略时解析发生在**代理服务器**
  （「DNS 解析永远在代理服务器进行」），本地不解析；只有命中 DIRECT 才本地解析。
  ⇒ 端点选址是**性能取向**，不是安全对错。`check_6` 只报 LOW 提示。
- ⭐ **`internet-test-url` 用国内 204** —— 它测的是「本机能不能上网」，
  用国内端点更贴切，且会被 `direct.txt` 接住走直连。
- `proxy-test-udp = apple.com@1.1.1.1` —— **专用 UDP 探针**。
  QUIC 类策略与 `smart` 组的 UDP 评分都要用它；不配的话 UDP 侧没有测速数据。

### 1.5 流量处理

```
udp-policy-not-supported-behaviour = reject
udp-priority = true
block-quic = per-policy
```

| 键 | 说明 |
|---|---|
| `udp-policy-not-supported-behaviour` | `https` 类型节点**完全不支持 UDP 转发**。现在 UDP 落到这类节点上会被拒绝（明确失败），而不是走一条不可预期的路径。 |
| `udp-priority` | 游戏模式：系统繁忙时优先处理 UDP 包。 |
| `block-quic = per-policy` | 代理策略默认已阻止 QUIC；显式写出来是为了"只在确实有用的地方放行"，而不是隐式依赖默认值。 |

### 1.6 局域网与安全

```
allow-wifi-access = true
allow-hotspot-access = true
proxy-restricted-to-lan = true
gateway-restricted-to-lan = true
```

后两者保持 `true`：即使上级网络的 DMZ / 端口转发配得潦草，
代理与网关的监听端口也不会暴露到当前子网之外。

### 1.7 Wi-Fi / 蜂窝

```
all-hybrid = false
wifi-assist = false
```

`all-hybrid = true` 会让**每条 TCP 连接和每次 DNS 查询**同时走 Wi-Fi + 蜂窝。
这是明确的耗电与流量代价，默认关掉。

### 1.8 Real-IP 豁免

```
always-real-ip = *.lan, *.local, *.localdomain, *.home.arpa, *.srv.nintendo.net, *.stun.playstation.net, *.xboxlive.com, stun.*, time.*.com, ntp.*.com, *.pool.ntp.org, *.market.xiaomi.com
```

游戏机 / NTP / STUN 主机名必须拿到**真实可路由地址**，否则：

- NAT 类型检测会失败（打游戏连不上）；
- 时间同步会失效；
- Apple 推送（依赖真实 IP）会异常。

> ⚠️ **`always-real-ip` 只改变"返回真实 IP 还是 Fake IP"，不改变路由去向。**
> 一个在 `always-real-ip` 里的域名，如果规则判它走代理，它依然走代理。
>
> ⚠️ 而且这些名字**不会自动被域名规则接住** ——
> 所以 `[Rule]` 段第 4 组专门为 `nintendo.net` / `playstation.net` / `xboxlive.com` 写了三条规则。

## 2. `[Proxy]` 段

### 2.1 为什么节点要写成占位符

本仓库是**公开模板**。节点地址 / 端口 / 密码 / SNI 全部替换为：

- IP：`203.0.113.x`（RFC 5737 保留的文档地址段，不会指向任何真实主机）
- 域名：`example.com`
- 凭据：`REPLACE_WITH_*`

发布前由 `skill/tests/architecture.sh` 的**占位符纪律**检查守着（非占位 IP 会直接判负）。

### 2.2 Hysteria 2

```
Node-A = hysteria2, 203.0.113.10, 52341, password=REPLACE_WITH_YOUR_PASSWORD, sni=REPLACE_WITH_YOUR_SNI
```

**`download-bandwidth` 刻意不设置** —— 它是**服务端**拥塞控制提示。
填错会导致 bufferbloat / 无谓重传。除非服务商明确公布数字，否则交给服务端决定。

### 2.3 中转链（`underlying-proxy`）

```
Node-C = https, cdn-relay.example.com, 443, username="…", password="…", underlying-proxy="Node-B", sni=cdn-relay.example.com
Node-D = https, 203.0.113.20, 443, underlying-proxy="Node-A", skip-cert-verify=true, sni=203.0.113.20
```

`underlying-proxy` 让连接先走到另一条节点，再由它出去连本节点。

- ⚠️ **`underlying-proxy` 指的名字必须真实存在**，否则 Surge 会以「无法解析 underlying-proxy」拒绝加载整份配置。
- ⚠️ **不要写成环**（A 的 underlying 指向 B、B 的指向 A）—— 会直接成环卡死。
- `reuse` 保持默认（`true`）：连接复用正是"每个请求省掉一次 TCP+TLS 握手"的关键。设成 `false` 是自找延迟。
- `Node-D` 的 `server` 是 **IP 字面量**，这是刻意的：IP 节点不产生"解析节点域名"那次查询 ——
  那是本配置里唯一**必定发生**的本地解析（不取决于你访问什么网站，只取决于连哪个节点）。

### 2.4 `https` 类型不支持 UDP

```
Node-D = https, ...
```

`https`（TLS 上的 HTTP 代理）**完全不支持 UDP 转发**。
落到这类节点上的 UDP 会被拒绝（由 `udp-policy-not-supported-behaviour=reject` 决定），
这也是它们只放在 `AI` 组、不做默认出口的原因。

### 2.5 ⚠️ 广告拦截与 `AD` 组的分层 / `skip-cert-verify` 的使用边界

**① 广告拦截不能指向策略组。**

```
AD = select, REJECT, DIRECT        ← 独立的手动开关，不被规则引用
```

`pre-matching` 的校验对策略要求严格（必须是 REJECT 族**策略本身**）。
策略组在运行时**可以**解析成 `DIRECT`，Surge 无法据此保证"一定拦得住"，
会直接拒绝加载整份配置并报「使用了非 REJECT 策略」。

⇒ 所以本模板让**拦截规则写字面量 `REJECT`**（换取 `pre-matching` 的 DNS 阶段
拦截能力），同时把 `AD` 组**保留为独立的手动开关**。两者职责分开：
规则负责「默认拦得住」，`AD` 负责「面板上有个干预入口」。

> 📌 这个分层顺手消掉一个 footgun：在面板上切换 `AD` **不会**意外改掉
> 规则的默认拦截行为 —— 想改默认行为，改规则那一行或注释掉整行。
> 若你要让 `AD` 直接接管开关，把那行策略改成 `AD` 即可，但**要一并去掉
> `pre-matching`**（见上），这是明确的取舍。

**② `skip-cert-verify` 只在中转链里用。**

`Node-D` 保持 `skip-cert-verify=true`，因为它的落地只讲 HTTP over 443，
TLS 由 `underlying-proxy` 那一段提供。**不要**给直连的落地节点开这个开关。

### 2.6 已注释的部分

```
# Node-E = vless, 203.0.113.30, 443, ...
```

VLESS Reality / XTLS **不是 Surge 的原生代理类型**。
写了会被跳过并告警，只增解析噪音 —— 所以留作注释示例。

## 3. `[Proxy Group]` 段

```
Proxy = smart, "Node-A", "Node-B", icon-url=…/Proxy.png
AI    = smart, "Node-C", "Node-D", icon-url=…/openai.png
AD    = select, REJECT, DIRECT, icon-url=…/AdBlock.png
```

### `smart` 为什么优于 `url-test`

`smart` 组的评分维度是：

- **真实连接的首字节延迟**（不是握手延迟）
- **TCP 重传丢包**（每 1% 约折算 50ms）
- **UDP 响应延迟**

并且它**记住每个站点用哪个策略最合适**。固定 5 分钟重测一次。

`url-test` 只测一个 URL 的延迟 —— 一个"对测试端点快、对你实际要访问的站点慢"的节点会被误选。

### 成员越少越快的取舍

两个组都只放 2 个节点。**这不是"没有更多节点"，而是刻意的**：
`smart` 的选择开销与成员数正相关，10 个节点里选优比 2 个慢得多，而收益递减。

### 已移除的配置项

原配置里有 `update-interval=3600`、`include-all-proxies=0`、`no-alert=0`、`hidden=0`：

- `update-interval` 只对**订阅型**组有意义，写在手工列成员的组上是空转；
- 后三个**都已经是默认值**，写出来只是噪音。

> ⚠️ 但要注意：`no-alert=0` / `hidden=0` 是**默认值**，而 `no-alert` / `hidden` 的
> **默认取值**在 Surge 不同版本间有过差异。若你的版本行为不是默认值，
> 就显式写出来。本模板选择"删掉等于默认值的东西"，理由是减少"看起来在做什么、
> 其实没做"的行。

### `AD` 组为什么还留着 `DIRECT`

它的定位是**独立的手动开关**：面板上随时可切，不牵动规则引擎。
留 `DIRECT` 是为了让这个开关**两个方向都能用** —— 想临时整体放行某类域名时
有个现成的落点，排查问题时也能一眼确认「放行链路本身是通的」。

> ⚠️ 但要说清职责边界：它是独立开关，**不由规则引用**，
> 所以切它不会改变规则的默认拦截行为（见 §2.5）。
> 想改默认行为，改规则那一行。

## 4. `[Rule]` 段 —— 12 条逐条

顺序就是一切。**自上而下，第一条命中即决定去向**。

| # | 规则 | 行 | 去向 | 要点 |
|---|---|:---:|:---:|---|
| ① | `RULE-SET,…/surge-white-guard.list` | 43 条 | `DIRECT` | **必须在 REJECT 之前**。这 43 条是会被黑名单误杀的功能域 |
| ② | `RULE-SET,…/surge-ads.list` | 3891 条 | `REJECT` | `pre-matching,extended-matching`。详细说明见下 |
| ③ | `RULE-SET,…/AI.list` | 49 条 | `AI` | `no-resolve`（纯域名集，不需要触发解析） |
| ④ | `DOMAIN-SUFFIX,nintendo.net` 等 | 3 条 | `Proxy` | 为 `always-real-ip` 的主机名准备 |
| ⑤ | `RULE-SET,SYSTEM` | 内置 | `DIRECT` | Apple 自己的激活 / 推送 / 定位 / 配对主机 |
| ⑥ | `RULE-SET,LAN` / `private.txt` | 内置 + 130 | `DIRECT` | `no-resolve`；LAN 含 IP-CIDR，不带会触发公网查询 |
| ⑦ | `RULE-SET,…/direct.txt` | 111169 条 | `DIRECT` | 国内直连**主承重墙**，纯域名 |
| ⑧ | `GEOIP,CN` | — | `DIRECT` | `no-resolve`；**必须放最后** |
| ⑨ | `FINAL,Proxy,dns-failed` | — | `Proxy` | `dns-failed` 见下 |

### ② 广告拦截的两个选项

| 选项 | 作用 |
|---|---|
| `pre-matching` | REJECT 提前到 **DNS 查询阶段和 TCP-SYN 阶段**求值。被拦的请求得到一个 "No Record" / TCP RST 就结束了，**连接层完全不会启动**。对一个广告密集的配置来说，这是最大的一笔 CPU 与耗电优化。 |
| `extended-matching` | 额外按 **TLS SNI / HTTP Host** 匹配。**专治「App 直连 IP、包里没有域名」导致域名规则失效的场景**。 |

> ⚠️ **`pre-matching` 只能跟 REJECT 系策略用**，`DIRECT` 加它无效。
> 所以白名单那行（①）不能写它。

### ⑦⑧ 为什么 `GEOIP,CN` 必须放最后

`GEOIP,CN` 是 **IP 类规则**，它需要一个已解析的地址。放在所有域名规则**之后**，
使走代理 / 被广告拦截 / 国内直连的流量都**不必做本地 DNS 查询**。

`no-resolve` 让它对未解析的主机名**跳过**，而不是暂停规则求值去解析它。

> ⚠️ **`no-resolve` 的代价**：它同时关掉了"靠解析判 IP 归属"这条直连路径。
> 所以国内域名**只能靠 ⑦ 的 `direct.txt` 接住** —— 这就是为什么 `direct.txt`
> 必须有 11 万条**域名**条目（而不是 IP 条目）。详见 [`docs/02` 案例 5](02-DNS为什么会泄露.md#案例-5--加了-no-resolve-之后国内网站全走代理了)。

### ⑨ `FINAL,Proxy,dns-failed`

`dns-failed`：万一规则求值因 DNS 失败而中断，用代理策略而不是让请求直接失败。
走代理的域名由节点**远端解析**，所以这一条既修好了失败，也避免了一次明文本地查询。

## 5. `[Host]` 与 `[URL Rewrite]`

```
[Host]
localhost = server:system
*.lan = server:system
*.local = server:system

[URL Rewrite]
^https?://(www\.)?g\.cn https://www.google.com 302
^https?://(www\.)?google\.cn https://www.google.com 302
```

`[Host]` 只列 Surge 自带 DNS 客户端可能处理错的特殊主机名。
`localhost` 内部就能解析，`*.lan` 已被 `exclude-simple-hostnames` + `LAN` 规则覆盖 ——
再映射一遍是冗余的，但保留它能让行为显式可读。

## 6. 必须替换的清单

**只有一处：`[Proxy]` 段。**

| 位置 | 现状 | 换成 |
|:-----|:-----|:-----|
| `Node-A` / `Node-B` 的 server / port / password / sni | `203.0.113.x` + `REPLACE_WITH_*` | 你的节点信息 |
| `Node-C` 的 server / username / password / sni | `cdn-relay.example.com` + `REPLACE_WITH_*` | 你的中转信息 |
| `Node-D` 的 server / sni | `203.0.113.20` | 你的落地 IP |
| `[Proxy Group]` 里三行的成员名 | `"Node-A"` … | 与 `[Proxy]` 里的名字**逐字一致** |

> ⚠️ **`underlying-proxy="Node-B"` / `"Node-A"` 也必须同步改。**
> 名字对不上时 Surge 会拒绝加载整份配置，并且报错位置在 `[Proxy Group]`
> 而不是 `[Proxy]` —— 容易找错地方。

## 7. `v0` 砍了什么

| 类别 | 移除的内容 |
|---|---|
| 策略组 | `AI`、`AD` |
| 规则 | 白名单守卫、`AI.list`、三条 `DOMAIN-SUFFIX`（游戏机域名） |
| 整段 | `[URL Rewrite]` |

**保留部分与 `v1` 逐字相同**：`[General]` 的 DNS / IPv6 / 测试端点段**一字未改**。

`v0` 的三点代价（写在 `v0.conf` 文件末尾，这里重复一次）：

1. **移除白名单守卫**后，黑名单误杀的功能域无人自动放行。实测那 43 条里含
   `github.com`、`jsdelivr.net`、`icloud.com` 这类高频域 —— 建议加回来。
2. **移除 AI 分流**后，AI 流量与日常流量共用 `Proxy` 出口。
   若你的 AI 节点和日常节点是分开的（`v1` 就是分开的），合流会导致 AI 流量跑到日常出口上。
3. **`v0` 的 `Proxy` 是 `select` 而不是 `smart`** —— 没有自动评分，节点挂了要手动切。

> ⚠️ 另外注意：移除三条 `DOMAIN-SUFFIX` 之后，`nintendo.net` / `playstation.net` /
> `xboxlive.com` 不再被专门接住，会落到 `direct.txt` 或 `FINAL → Proxy`。
> 它们仍在 `always-real-ip` 里（拿真实 IP），但路由去向不再确定。
