# 06 · 实测数据与设计取舍

> 本篇记录**改配置之前先量一遍**得到的数字。
>
> 为什么要有这篇：DNS 泄露方案有太多"看起来对"的写法，光靠读配置读不出谁快谁省电。
> 这些数字决定了模板里几处看起来"多此一举"的取舍 —— 比如 `pre-matching`
> 为什么值得单开一条规则；也记录了一个**被否掉的改动**（§4，测试端点）。
> 后者的价值恰恰在于：它证明"减少解析面"这条原则**不能无差别套用**。

---

## 1 · 泄露面的量化

同一台设备、同一次冷启动，只改一处配置，看明文 `UDP:53` 的出现次数。

| 配置状态 | 明文 :53 次数 | 说明 |
|:---------|:-------------:|:-----|
| 裸连（无 Surge） | 全程 | 基线，不作对数 |
| Surge 默认 DNS | 数十次 | 系统 DNS 查询 + 旁路设备 |
| 仅加 `encrypted-dns-server` | ~ 12 次 | 端点主机名的**引导解析**仍然明文 |
| 再加 `hijack-dns` | ~ 3 次 | 旁路设备收口，剩引导与规则触发 |
| 再加 IP 规则 `no-resolve` | **0** | 三处收口完成 |

> ⚠️ 这些是单机单次抓包的读数，**只用于判断"有没有收口"，不要当成绝对值**。
> 不同系统版本、不同路由器环境差异很大。要复现请自己抓一遍。

关键在于**逐项下降的拐点**：加了 `no-resolve` 之后从 3 掉到 0，说明规则触发的解析
才是最后那一条通路，也说明前两步单独做都不够。

## 2 · `pre-matching` 的收益

`pre-matching` 让 REJECT 在 **DNS 查询 / TCP SYN 阶段**就生效，不建连、不解析。
拿广告拦截那 3891 条规则集量：

| 指标 | 不开 `pre-matching` | 开 `pre-matching` |
|:-----|:-------------------:|:-----------------:|
| 命中域的 DNS 查询 | 走完解析再拒 | 查询即拒 |
| 每条命中的建连次数 | 1（TCP 握手） | **0** |
| 批量规整广告页面的完成时间 | 基线 | 明显更短 |

这是**全模板最大的一笔电池优化**，原因是它省掉的不只是带宽，还有"解析 → 建连 →
等首字节 → 丢弃"这一整串唤醒。移动端省电的关键从来不是省流量，是少唤醒。

### 2.1 但 `pre-matching` 有个硬约束

`pre-matching` 的规则，**策略必须是字面量 `REJECT` 家族**，不能是策略组。

原因：预匹配发生在**还来不及决定出口**的阶段。策略组的结果依赖运行时评分
（`smart` 会按首字节延迟选节点），而这一步在预匹配阶段还没发生。更糟的是，
若把组名写进 `pre-matching`，而该组在运行时可能解析成 `DIRECT`，Surge
**会直接拒绝加载整份配置**。

⇒ 所以本模板的广告拦截写的是字面量 `REJECT`（换取 `pre-matching` 的 DNS 阶段拦截），
而旁边那个 `AD = select, REJECT, DIRECT` 组作为**独立的手动开关**保留 ——
两者职责分开：规则负责「默认拦得住」，`AD` 负责「面板上有个干预入口」。

## 3 · `smart` 组评分的三个维度

`smart` 不是"取最低延迟"，它按三个信号打分：

| 维度 | 权重体现 | 为什么算它 |
|:-----|:---------|:-----------|
| 真实连接首字节延迟 | 主项 | 比 ping 更贴近实际体验 |
| TCP 重传率 | 每 1% 约折算 50 ms | 丢包比延迟更致命，按时延折算才能进同一套评分 |
| UDP 响应延迟 | 单列 | `https` 类型**不支持 UDP 中继**，UDP 表现必须单独看 |

重测间隔 5 分钟，并**按站点记住最优策略** —— 所以你会看到 `smart` 对
「同一个节点，访问 A 站快、访问 B 站慢」这种情况有自适应能力。

> 📌 由此得出一个模板里的硬规则：**`https` 类型的节点不要放进承担 UDP 的组**。
> 本模板把 `Node-C` / `Node-D`（都是 `https`）放进 `AI` 组，因为 AI 流量的
> 主要诉求是稳定长连接与不被降级，不靠 UDP。反过来，需要 UDP 中继的场景
> （游戏、部分 QUIC 应用）要走 `hysteria2` 的节点。

## 4 · 代理测试端点的选择（**性能探针，不是泄露通道**）

这一节记录一个**被否掉的改动**，因为它是个典型的"原则误套用"。

曾把 `proxy-test-url` 从 `gstatic.com`（境外）改成 `connect.rom.miui.com`（境内），
理由是"减少周期性解析面"。**这个理由是错的**，原因两条：

| 端点 | 域名性质 | 它实际测的是什么 | 结论 |
|:-----|:---------|:-----------------|:-----|
| `http://www.gstatic.com/generate_204` | 境外 | 含国际段的真实路径 —— 对选节点有参考价值 | ✅ 保留 |
| `http://connect.rom.miui.com/generate_204` | 境内 | 境内 RTT；节点在境外时那段路由与真实路径不同 | ⚠️ 不是更准 |

**为什么"泄露"这个理由不成立**：官方 KB 明确 —— 「当使用代理策略时…Surge 总是会
使用域名向代理服务器发起请求，也就是说 **DNS 解析永远在代理服务器进行**」。
本地解析只在命中 DIRECT 时发生。所以端点域名**不是**一条泄露通道，
它是给 `smart` / `url-test` 打分的**性能探针**。

**最终取舍**：按用途分工，而不是一律求境内 ——

- `internet-test-url`（连通性检测）→ 国内 204。测的是「本机能不能上网」。
- `proxy-test-url`（`smart` 打分）→ **保持境外 `gstatic.com`**。测含国际段的真实路径。

⇒ `check_surge_dns.py` 的 `check_6` 相应**只报 LOW 提示，不计入风险等级**。

⚠️ 注意区分：`proxy-test-url` 决定**TCP 测速用什么**，`proxy-test-udp` 决定
**UDP 测速用什么**。后者用的是 `apple.com@1.1.1.1`，不产生域名解析面。

## 5 · 为什么只有一份配置

本仓库只提供**一份懒人配置**（`lazy.conf`），不再按"完整版 / 极简版"分叉。

### 5.1 分叉的代价：同一件事写在两个地方

早先有过 `v1`（完整分流）与 `v0`（极简版）两版并行的设计。问题在于：

> **同一件事写在两个地方，早晚会只改一处。**

两版共享同一份 DNS 段，任何一处防泄露改动都要同步两份 —— 这是纯粹的维护负担，
而且漏改的后果是**静默的**（另一版悄悄多了一个泄露面，没人发现）。

### 5.2 改成"一份配置 + 一份 min 形态"

现在只保留：

| 文件 | 形态 |
|:-----|:-----|
| `lazy.conf` | 带注释，用来读与改 |
| `lazy.min.conf` | 纯配置，用来导入 |

**两份内容一致，只差注释。** 这条由 `skill/tests/architecture.sh` 断言 ——
它会逐字节比对两份的 **16 个 DNS 相关键**，只改一份立刻报红。

这比"两个版本"轻得多：**没有版本分叉，只有形态分叉。**

### 5.3 想更轻怎么办

不要另开一个版本，**在 `lazy.conf` 上直接删**。可删的东西按收益排序：

- AI 分流（`AI` 组 + `AI.list` 那条规则 + 3 条游戏机域名）
- `AD` 组（不被规则引用的手动开关）
- `[URL Rewrite]`

⚠️ 但 `direct.txt` / `GEOIP,CN` / 白名单守卫**不能删** ——
理由见 [`docs/05`](05-分流与no_resolve必须成对交付.md) 与 §3。

## 6 · 数据是怎么来的 / 怎么复现

本仓库**刻意不挂 CI / 任何自动化**（理由见 [`skill/README.md`](../skill/README.md)），
所有数字都是本地跑出来的：

```bash
# 结构审计（不联网）
python skill/scripts/check_surge_dns.py profiles/lazy.conf

# 规则集内容审计（需要联网，拉一遍所有 RULE-SET）
python skill/scripts/audit_ruleset_content.py profiles/lazy.conf

# 分流覆盖（需要联网，拿域名走一遍规则）
python skill/scripts/audit_routing_coverage.py profiles/lazy.conf

# 全部一起
bash skill/tests/run.sh
```

当前读数见 [`08-审计读数`](08-审计读数.md)。

> ⚠️ 抓包类数字（§1）**没有脚本**，必须人工用 Charles / Stream / Wireshark 之类抓。
> 审计脚本只覆盖**静态可判定**的部分 —— 这是刻意的边界，不是遗漏。
