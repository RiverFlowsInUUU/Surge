# 09 · 注意事项

> 使用前值得先看一遍的几条。拿配置见 [`README`](../README.md) 的 [📥 两份配置](../README.md#-两全其美皆合心意)。

---

| 项目 | 说明 |
|:----:|:-----|
| 🧩 **节点必须自己填** | `[Proxy]` 段全是占位符（`203.0.113.x` + `REPLACE_WITH_*`）。不填则 `FINAL → Proxy` 是断的 —— **所有走代理的流量都不通** |
| 🧭 **先选分工，再选形态** | 两份配置是**分工关系**不是版本关系：`lazy.conf`（3 组 / 14 条，全量一个出口）与 `routing_v3.conf`（26 组 / 24 条，按应用 + 按地区）。**选一份用，不要叠加**。对比见 [README · 两份配置](../README.md#-两全其美皆合心意) |
| 📄 **每份都取一种形态** | [`profiles/lazy.conf`](../profiles/lazy.conf)（带注释）与 [`lazy.min.conf`](../profiles/lazy.min.conf)（纯配置）**内容一致**，只差注释；`routing_v3.conf` / `routing_v3.min.conf` 同理。改配置请改 `.conf` 那份，改完把改动同步到 `.min.conf` —— 阶段 3 的架构检查会逐字比对两份的 DNS 段 |
| ✈️ **分流版还需填订阅** | `routing_v3.conf` 的 `Airport` 组是 `policy-path=<订阅 URL>`，token 为占位符。**不填则只能靠 `[Proxy]` 的本机节点**（地区组会依据节点名里的地区关键词筛选，也能用）。 |
| 🌏 **分流版的地区组可能为空** | 地区组靠 `policy-regex-filter` 匹配**节点名里的地区关键词**。节点名不含某地区关键词时该组为空 —— Surge **不会**因此拒绝加载，但指向它的规则会断流。导入后到面板上确认哪几个组是空的；填词方法见 [`docs/11`](11-分流版设计.md#4--地区名怎么筛正则) |
| 🔁 **改地区关键词要改两处** | `Other Regions` 的负向断言把另外 6 个地区组的关键词抄了一遍。改完立刻跑 `python skill/scripts/audit_region_filters.py profiles/routing_v3.conf` |
| 🔄 **规则集刷新** | 全部远程 `RULE-SET` 都带 `update-interval=86400`（按天刷新）。这是**必须**的 —— 上游新收录的广告域名否则会一直命不中 |
| 🧪 **全部本地完成** | 本仓库**刻意不挂 CI / 任何自动化**（理由见 [`skill/README.md`](../skill/README.md)）—— 改完 profile 在仓库根目录跑一次 `bash skill/tests/run.sh` 即可 |
| ⚠️ **"审计全绿"不等于"配置可用"** | 本项目的审计脚本只覆盖**静态可判定**的部分。拦截效果、误杀、节点可用性必须实测 —— 这是 Egern 项目连续 5 次"脚本全绿、实测仍有问题"换来的结论 |
| 🔐 **不要把真实节点提交回来** | 本仓库是公开模板。改完本地用可以，`git push` 前跑一次阶段 3 的 `architecture.sh` —— 它会拦住非占位 IP 与未替换的凭据 |
